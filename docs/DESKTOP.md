# Accora — تطبيق سطح المكتب (Electron)

> حالة المستند: **مجرّب فعليًا بالكامل على لينكس، من الصفر إلى نافذة حقيقية شغّالة** — بنيت الحزمة النهائية (`AppImage`) بنفس الأمر يلي رح يستخدمه أي مبرمج لاحقًا، وشغّلتها كملف تنفيذي حقيقي (مو "وضع تطوير") على مستخدم عادي (مو root)، وأخذت لقطة شاشة حقيقية للنافذة وهي شغّالة. نسخ Windows وmacOS مبنية بنفس المنطق لكن **ما قدرت أشغّلها فعليًا** لأنه بيئة هاي الجلسة لينكس فقط — موضّح بالتفصيل بالقسم 4.

---

## 1. شو هاد التطبيق

`apps/desktop` هو غلاف Electron حقيقي حول أكورا — تطبيق سطح مكتب عادي، تفتحه بضغطة واحدة، **بدون** أي حاجة يدوية من المستخدم:
- ما في حاجة لتثبيت Docker.
- ما في حاجة لتثبيت PostgreSQL.
- ما في نافذة Terminal تظهر.
- ما في تبويب متصفح — نافذة برنامج حقيقية.

أول ما يفتح المستخدم البرنامج، بيصير هيك تلقائيًا بالترتيب:
1. تجهيز قاعدة بيانات PostgreSQL مدمجة (حقيقية، مش محاكاة) خاصة بهاد التطبيق فقط — أول مرة بس بتصير التهيئة، بعدها بتبقى موجودة.
2. تحديث هيكل قاعدة البيانات لآخر نسخة (نفس آلية الترحيلات المستخدمة بالخادم العادي).
3. تعبئة البيانات الأساسية (العملات، الصلاحيات، قوالب الأدوار، دليل الحسابات الافتراضي).
4. تشغيل خادم أكورا (نفس كود `apps/api` بالضبط، مبني ومترجم) كعملية خلفية.
5. فتح نافذة البرنامج على واجهة أكورا (نفس كود `apps/web` بالضبط، بدون أي تعديل).

كل هاد بيصير وراء شاشة تحميل بسيطة بالعربي، وبيوقف تلقائيًا (يطفي قاعدة البيانات بأمان) لما يسكر المستخدم البرنامج.

---

## 2. كيف تبنيه (لأي مبرمج رح يشتغل على هاد الجزء لاحقًا)

```bash
cd apps/desktop
npm run package
```

هاد الأمر الواحد بيعمل كل شي: يبني `apps/api` و`apps/web`، يجهّز نسخة كاملة ومستقلة من الخادم (مع كل مكتباته) جوا `apps/desktop/resources/`، يبني تطبيق Electron نفسه، وينتج الملف التنفيذي النهائي بمجلد `apps/desktop/release/`.

**ملاحظة مهمة لمن يطور بهاد الجزء**: `apps/desktop` بيستخدم `pnpm` بشكل طبيعي للتطوير اليومي (`npm run start` لتجربة التطبيق بوضع التطوير). بس خطوة التعبئة النهائية (`npm run package`) بتعيد تثبيت مكتبات `apps/desktop` نفسها بـ`npm` عادي بدل `pnpm` — هاد مو خطأ، هو مقصود ومشروح بالتفصيل جوا `scripts/prepare-resources.mjs`: أداة `electron-builder` يلي بتبني الحزمة النهائية ما بتفهم طريقة `pnpm` بتنظيم المكتبات (رموز/اختصارات ملفات معقّدة)، فبنحولها لنسخة عادية بسيطة وقت التعبئة بس.

## 3. شو جرّبته فعليًا وشو ما جرّبته

### ✅ مجرّب فعليًا بالكامل (لينكس):
- بنيت الحزمة النهائية `AppImage` بالضبط بنفس أمر `npm run package` يلي أي حدا رح يستخدمه.
- شغّلت الملف التنفيذي الناتج (`release/linux-unpacked/accora`) — مو بوضع تطوير، الملف الحقيقي يلي بيوصل للمستخدم — كمستخدم عادي بدون صلاحيات مدير (بالضبط متل أي مستخدم حقيقي).
- شفت بعيني (عبر لقطة شاشة حقيقية) إن قاعدة البيانات المدمجة اشتغلت، الترحيلات الـ15 اتطبقت، البيانات الأساسية اتعبت، الخادم اشتغل، والواجهة ظهرت صح وبالعربي واتجاه الكتابة من اليمين لليسار سليم.
- جربتها من الصفر (بدون أي مكتبات مثبتة مسبقًا) عشان أتأكد إنها بتشتغل عند أي حدا يسحب المشروع لأول مرة، مش بس عندي.
- تأكدت إن إقفال البرنامج بيطفي قاعدة البيانات بأمان (مو قطع فجائي).

### ⚠️ ما قدرت أجربه فعليًا (وكيف تم حل هاي الفجوة):
بيئة هاي الجلسة الحالية **لينكس فقط**، فما قدرت أشغّل ملف `.exe` (Windows) ولا `.dmg` (macOS) فعليًا بنفسي. جربت أبني `.exe` عبر أداة تحويل (Wine) لتوليده من لينكس، لكن طلعت مشاكل توافق داخلية بهاي البيئة ما حبيت أخاطر فيها — ملف تثبيت غير مضمون أسوأ من عدم وجوده.

**الحل**: أضفت ملف إعداد (`.github/workflows/build-desktop.yml`) خاص بـ GitHub Actions — بيبني البرنامج تلقائيًا على أجهزة Windows وmacOS وLinux **حقيقية** (يوفرها GitHub نفسه)، مش محاكاة ولا تحويل. من صفحة المشروع على GitHub، تبويب "Actions"، اختر "Build Desktop App"، اضغط "Run workflow"، وانتظر بضع دقائق — بيطلعلك ثلاث ملفات جاهزة للتحميل (Windows/.exe، macOS/.dmg، Linux/.AppImage)، كل وحدة مبنية فعليًا على نظامها الحقيقي.

## 4. تفاصيل تقنية (للمبرمجين)

- **قاعدة البيانات المدمجة**: مكتبة [`embedded-postgres`](https://www.npmjs.com/package/embedded-postgres) — بتجيب نسخة PostgreSQL حقيقية جاهزة لكل نظام تشغيل، وبتديرها برمجيًا (تشغيل/إيقاف) بدون أي تثبيت يدوي من المستخدم.
- **تشغيل الخادم**: نفس كود `apps/api` المبني (`dist/`)، بيشتغل كعملية فرعية منفصلة، بيتصل بقاعدة البيانات المدمجة.
- **عرض الواجهة**: خادم بسيط داخلي (`src/static-server.ts`) بيعرض ملفات `apps/web` المبنية، وبيمرر طلبات `/api` للخادم — بنفس منطق `vite.config.ts` تمامًا، عشان نفس بناء الواجهة يشتغل بدون أي تعديل سواء بوضع التطوير أو داخل التطبيق النهائي.
- **الأمان**: كل الأسرار (كلمات مرور JWT، كلمة مرور قاعدة البيانات) محلية بالكامل على جهاز المستخدم نفسه، ما بتطلع لأي مكان خارجي.

## 5. تشغيل الاختبارات

الاختبارات الخاصة بمحرك الحسابات نفسه (`apps/api`) ما تأثرت بإضافة تطبيق سطح المكتب — لسا كلها ناجحة:
```bash
cd apps/api
pnpm test   # 76/76
```
